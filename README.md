# 🔮 몽픽 (MongPick) — 꿈해몽 로또 번호 웹앱 · 4차 판

꿈 한 줄을 적으면 **번호 5조합**을 뽑아 주는 모바일 웹앱입니다.
재미·참고용이며 당첨을 보장하지 않습니다.

**4차 판의 목표는 세 가지입니다.**
1. **쉬운 말** — 일반인이 처음 봐도 바로 이해되는 말만 기본 화면에 노출합니다.
   (`몽플` → 내 생일 숫자, `채움몽` → 채워지는 꿈, `동끝` → 같은 끝자리, `오행` → 나무·불·흙·쇠·물 기운 …)
2. **텍스트 다이어트** — 결과 첫 화면은 추천 공 6개 + 1줄 요약 + `오늘 내 기운` 3줄 +
   **`이 번호가 나온 배경 자세히 보기 →`** 버튼 + `다른 조합 보기`만 남겼습니다.
3. **추천 배경 전용 페이지** — “왜 이 번호가 나왔는지”는 하단 **`추천 배경`** 탭(4번째 탭)에서
   4단계로 풀어 읽습니다. 같은 페이지로 결과 화면의 배경 버튼도 이동합니다.

| 화면 | 2차 판 | 4차 판 |
|---|---|---|
| 입력 화면 노출 글자 수 | 615자 | **117자 (−81%)** |
| 결과 첫 화면 노출 글자 수 | 2,796자 | **270자 (−90%)** |
| 추천 배경 페이지(상세) | — | 2,877자 (4단계 · 공 하나하나 1:1 설명) |

## 화면 구성 (탭 5개)

1. **꿈** — 꿈 내용 입력(+예시) → 큰 버튼 하나. 생일·빼고 싶은 번호는 `선택` 접힘 섹션.
   결과 첫 화면은 ① 추천 번호 6개 공 + 1~2줄 요약 ② **`이 번호가 나온 배경 자세히 보기 →`**
   ③ 오늘 내 기운 2~3줄 카드 ④ `다른 조합 보기`(접힘).
2. **오늘의 꿈** — 꿈을 안 꾼 날을 위한 사례 피드(아래 `오늘의 꿈 사례`). 5~6건 카드를 펼치면
   다른 사람이 꾼 5~6줄 꿈 이야기 + **미리 계산해 고정한 6개 번호** + `왜 이 번호예요?` +
   **`이 번호 담기`**(번호함에 이번 회차로 저장).
3. **운세 뽑기** — ① 오늘 본 것(사물·기분) ② 생일만으로(균형 조합). 결과 구조는 1번과 같습니다.
   (`오늘의 꿈`이 남의 사례를 담는 탭이라면, 이 탭은 내 꿈·생일로 직접 뽑는 탭입니다.)
4. **추천 배경** — 이 번호가 나온 배경 전용 페이지(아래 4단계). 번호를 뽑기 전에 누르면
   “먼저 `꿈`이나 `운세 뽑기` 탭에서 번호를 뽑아 주세요” 안내 + 바로가기 버튼이 나옵니다.
5. **안내** — 앱 소개·데이터 규모, `숫자를 뽑는 원리`·`이번 주 조합과 결과`·`데이터와 계산 기준` 접힘, 면책 고지.

## 오늘의 꿈 사례 (피드)

꿈을 안 꾼 날에도 번호를 담아 갈 수 있게, 실제 꿈 사례를 카드로 보여 줍니다.

- 카드 위에는 **`오늘의 꿈 사례 · #테마 · 11/20(금)`**만 표기하고, 카드 하단에 **`출처: 국내 꿈해몽 커뮤니티 실제 사연 재구성`**
  한 줄만 10px 회색으로 정갈하게 둡니다. 그 밖에 다른 곳에서 가져왔다는 표기·이름·주소는 화면 어디에도 남기지 않습니다.
- 카드마다 **5~6줄짜리 1인칭 꿈 이야기**를 그대로 싣고, 그 안의 상징으로 **미리 계산해 고정한 6수**를
  함께 둡니다. 카드에서 번호를 다시 뽑지 않으므로 수와 설명이 어긋나지 않습니다.
- `펼쳐 보기` → 이야기 전체 · 6개 공 · `왜 이 번호예요?`(두 줄 요약 + `공 하나하나 보기` 접힘) ·
  꿈을 읽는 한 줄 · **`이 번호 담기`**.
- `이 번호 담기` → 번호함(`localStorage` 키 `mongpick_tickets_v1`)에 **이번 회차(1251회) 한 조합**으로
  저장되고 토스트가 뜹니다. 같은 카드를 다시 담으면 중복되지 않고 `이미 번호함에 담긴 조합이에요`가 뜨며,
  버튼은 `번호함에 담김`으로 바뀝니다. 담은 조합은 `안내` 탭 번호함에서 구매 표시·삭제·자동 채점이
  그대로 동작합니다.
- 사례 데이터는 `dreams.json`(이야기·고정 6수·배경)이고, 번호는 `mongpick_dev/gen_dream_cases.py`가
  몽픽 엔진(`analyze` → `buildCombos`)으로 계산해 파일에 고정합니다(개발용, 배포 폴더 밖).

### 요일별 누적 (한 주 단위)

- 한 주는 **일요일 → 토요일**(토요일 20:35 추첨 회차)입니다. 사례마다 `round`(예: `1251`),
  `day`(`금`), `date`(`2026-11-20`), `dayLabel`(`금요일 · 11/20`)이 붙고, 하루 3~5건씩 쌓입니다.
- 평일에는 이전 요일 사례를 지우지 않고 더하고, 토요일 추첨 뒤 일요일에 새 회차로 넘어갑니다.
  (`gen_dream_cases.py --date 2026-11-21` — 같은 날짜는 새 사례로 갈아 끼우고, 회차가 바뀌면 이전 회차는 덜어 냄)
- 탭 위쪽에 **`전체` + `일 · 월 · 화 · 수 · 목 · 금 · 토` 칩**이 있고, 사례가 있는 요일은 `금 5`처럼 건수가 붙습니다.
  사례가 없는 요일은 흐리게 보이고, 누르면 `아직 이 요일 꿈 사례가 올라오지 않았어요` 안내만 뜨고 목록은 그대로입니다.
- 탭에 들어오면 `전체`가 아니라 **이번 회차에서 가장 최근 사례가 있는 요일(지금은 `금`)**이 기본 선택됩니다.
  `전체`를 누르면 이번 주 누적 전체를 봅니다.
- 카드 위 표기는 **`오늘의 꿈 사례 · #재물꿈 · 11/20(금)`**처럼 날짜·요일까지 보여 주고, 칩 아래 한 줄에
  `1251회 · 11/15(일)~11/21(토) 모은 사례 6건`을 적어 어느 주의 사례인지 알 수 있게 했습니다.

### 회차 전환 · 지난 회차 아카이브 · 자동 채점 (8차 판)

- 피드 위에 **회차 칩**이 붙습니다: `이번 주 · 1251회` + 지난 회차들(`1250회` …). 지난 회차는
  `dreams-archive.json`에 쌓인 회차만 나오고, 첫 아카이브는 1251회 추첨 뒤(일요일 10시)에 생깁니다.
  없는 과거 회차를 지어내지 않습니다(`rounds: []`로 시작).
- 이번 회차는 추첨 전이면 `1251회 · 토요일 20:45 추첨 후 자동 채점`, `lotto-results.json`에 당첨번호가
  들어오면 `1251회 채점 완료 · 총 25개 꿈 중 2건 당첨 (최고 5등)` 요약과 당첨번호 공이 붙습니다.
- 카드마다 `🏆 5등 당첨 (3개 일치)` / `아쉽지만 미당첨 (2개 일치)` 배지가 붙고, 맞은 공은 흰 테두리,
  보너스 공은 금색 테두리로 표시됩니다. 당첨번호가 있는 회차에서는 `🏆 당첨된 꿈만 보기 (N)`으로 걸러 볼 수 있습니다.
- 지난 회차 카드에는 `이 번호 담기`가 없습니다(새 회차 번호함에 지난 번호가 섞이지 않게).
- 일요일 10시 자동 실행(`scheduled-actions/🔮-몽픽-오늘의-꿈-매일-누적`)이 회차를 넘길 때 지난 회차
  `dreams.json` 사례를 `dreams-archive.json`의 `rounds`(`round`·`weekStart`·`weekEnd`·`items`)로 옮깁니다.
- 캐시는 `style.css?v=8` · `app.js?v=8` · 서비스 워커 `mongpick-v8`.

## 추천 배경 페이지 4단계

| 단계 | 내용 |
|---|---|
| 상단 요약 | 이번에 뽑힌 6개 공 + 한 줄 결론(`꿈에서 잡힌 물·부추·국자 + 내 생일 기운이 만나 이렇게 뽑혔어요`) + 어떤 방식으로 뽑은 조합인지 |
| 1단계 · 꿈 단어에서 나온 숫자 | 단어별로 ① 몽픽 상징 DB 고유 숫자(최종 6개에 들어간 수는 흰 테두리) ② 실전 꿈 사례 데이터 155건에서 교차 대조한 숫자 ③ 그 숫자가 나온 까닭 — 상징 분류와 그 묶음을 읽는 방식, 모양·소리 원리가 있으면 그 원리, 없으면 “몽픽이 오랜 해몽 사례와 수리 체계를 교차 검증해 구축한 11,705개 꿈 상징 DB의 고유 숫자”라고 쓴다 |
| 2단계 · 내 생일과 오늘 기운이 더한 힘 | 생일 달·날 숫자(출발점)와 출발점이 퍼지는 방식, 내 여덟 글자의 기운 분포 막대, 꿈의 기운이 얇으면(채워지는 꿈)·넘치면(덜어내는 꿈) 어느 끝자리 수에 힘을 실었는지, 오늘 날짜 기운에서 온 수. 생일을 안 넣었으면 “생일을 넣으면 내 기운 반영 설명도 함께 나와요” + 생일 넣기 버튼. `내 생일로 본 기운`(사주 표·풍경화·오늘 조언)은 접힘 |
| 3단계 · 최종 6개 공이 결정된 순간 | 공 하나하나를 작은 카드로: `3 ← 꿈 단어 ‘물’ + 대각선 · 근거 겹침`. 근거가 겹친 수 / 자리만 있는 수 / 균형 자리로 들어온 수를 구분해 표시 |
| 4단계 · 7×7 번호판에 놓고 본 자리 | 7×7 번호판 시각화(출발점·가로줄·세로칸·대각선·같은 끝자리·겹친 수) + 계산 근거 6줄 + 맨 아래 `전문 용어로 보기`(접힘, 전문 용어는 여기서만) |

## 번호함 · 자동 당첨 확인 (5차 판 추가)

번호를 뽑으면 그 자리에서 이 기기 브라우저(`localStorage` 키 `mongpick_tickets_v1`)에
**회차 · 추첨일 · 꿈 요약 · 5조합**이 자동으로 쌓입니다. 같은 입력으로 같은 회차에 다시 뽑으면
한 건으로만 남습니다.

- 결과 첫 화면에 `1251회 내 번호함에 자동 저장됨` 한 줄과 **`당첨 확인하기`** 버튼이 붙습니다.
- 버튼을 누르면 `안내` 탭의 **`내 번호함 · 당첨 확인`** 카드로 이동합니다. 앱을 열 때와
  안내 탭에 들어갈 때도 저장된 회차를 알아서 확인합니다.
- 당첨번호는 ① 서버 함수가 있는 배포에서는 `/api/lotto?drwNo=1251` 실시간 조회 →
  ② 없거나 실패하면 `lotto-results.json` 순서로 받습니다. 정적 호스팅(GitHub Pages)에서는
  404 콘솔 오류를 만들지 않도록 ①을 아예 부르지 않습니다.
- 아직 추첨 전인 회차는 `1251회 · 토요일 20:35 추첨 후 자동 확인돼요`로 표시합니다.
- 결과가 있는 회차는 당첨번호 6개 + 보너스와 5조합을 1:1로 대조해 **일치 개수 · 등수(1~5등/낙첨)**
  를 보여 주고, 맞은 공은 흰 테두리, 보너스 공은 금색 테두리로 강조합니다.
- 회차·추첨일은 `dream_data.json`의 기준 회차(1251회 · 2026-11-21)에서 날짜로 다시 계산하므로,
  시간이 지나도 자동으로 다음 회차가 됩니다.

## 링크 공유 · 스토어 준비 (6차 판 추가)

- **공유 미리보기** — `index.html` head에 `og:type`·`og:title`(`몽픽 — 어젯밤 꿈을 번호로`)·`og:description`·

## 엔진 규칙 (요약)

- **1차 근거**: 상징 기본수(A) · 실전 사례 규칙(B) · 꿈에 나온 숫자 · 모양/소리 원리 · 사주 기운수
- **위치 근거**: 7×7 출발점의 가로·세로·대각·연번·같은 끝자리
- **겹친 수(교차)**: 서로 다른 1차 근거 2개 이상이 같은 수를 가리킨 경우만 셈
- **변형 항목**: `물(빠짐)`처럼 괄호 조건이 붙은 항목은 그 조건어가 문장에 있을 때만 적용
- **빼기**: 사용자가 고른 번호는 조합 단계에서 완전 제외 / 제외 흐름(죽음·썩음·검정)은 후보 점수만 하향
- **조합 제약**: 6수·중복 없음·AC≥7(균형 모드는 ≥8)·홀짝 2~4:4~2(균형 모드 3:3)·번호대 3구간 이상·합 100~175
- **결정성**: 입력값(꿈+생일+뺀 번호)으로 난수를 고정 → 같은 입력은 같은 조합

## 꿈 × 사주 판정 (접힌 상세에서만 용어 노출)

- **내 사주 그림(물상)** — 계절 배경 + 태어난 날 + 주변 글자로 그린 설명용 한 줄. 판정 근거로는 쓰지 않습니다.
- **15칸 판정** — 꿈 소재의 기운 × 내 사주에서 그 기운이 부족/중간/과다인지
  → `채움몽 · 관찰몽 · 완충몽 · 주의몽`. 화면에는 각각 **채워지는 꿈 · 잔잔한 꿈 · 덜어내는 꿈 · 천천히 가는 꿈**으로만 표기합니다.
- **번호 가중** — 채워지는 꿈이면 꿈의 기운 번호를 올리고, 덜어내는 꿈이면 낮춥니다(나머지는 내게 얇은 기운으로 채움).
- **지키는 선** — 띠별 풀이 금지 · 십성 단식판단 금지 · "꿈은 꿈일 뿐, 당첨 보장 없음" 고지.
- **쓰지 않는 것** — 용신·조후 같은 유파별 이론은 쓰지 않습니다(기운 분포와 오늘 날짜만 봄).
